# ListoLista: audit of the old apps (product + engineering)

Date: 2026-10-21. Auditor: Claude (subagent "app"). Scope: `data/cache/old/main/` (live today), `data/cache/old/checkpoint1/` (Sept 2026 rebuild, never shipped), `data/cache/old/local-2024/`, plus every historical `index.html`/`sandbox.html` on `origin/main` (read-only `git show`), because older deployed versions also wrote to the same origin's localStorage.

Legend: **V** = verified by running code (harness in headless Edge 155, Node 24, or a network probe); **C** = from reading the code (file:line given); **unverified** = could not check.

## 0. TL;DR

- The live site is exactly `old/main/index.html` (CRLF-normalized identical; `Last-Modified: Fri, 25 Sep 2026 21:26:13 GMT`). `sandbox.html` is also live. There is no manifest or service worker on the live origin (both 404). **V** (`understand/scripts/fetch_live.mjs`)
- Seven different localStorage layouts have been written to `vdm285.github.io` by deployed versions since 2024. Only one of them (`listolista_index_*` + `listolista_data_*`) is the current one. The checkpoint-1 migration (`migrateV1`) reads only that one and silently ignores `listolista_v1` (Dec 2025), `listolista_v2_current_*` (12 Jan 2026), and `inputs` (2024). **V** (harness step C2)
- The public HiveMQ broker holds **zero** retained `listolista/#` messages today; a control probe on `testtopic/#` received 33 retained messages, so the probe works. Old shared lists therefore exist **only on phones**: an old `?room=` link opened on a phone that never had the list cannot recover anything. **V** (`scripts/probe_hivemq.mjs`)
- Two data bugs in the live app matter for migration. (1) Titles are stored UPPERCASE: `innerText` applies the CSS `text-transform`, so the original case is lost. (2) The "Mis Listas" index title is overwritten with "NUEVA LISTA" each time a list is opened. The importer must take titles from `listolista_data_<id>.meta.title`, not from the index. **V**
- Worth keeping from checkpoint 1: undo instead of confirm, long-press sheet with inline edit, comma splitting, a collapsible "Tachados (n)", a status dot on *Compartir*, Back closing sheets, cross-tab merge. Drop or rethink: the Cloudflare relay (it needs the owner's account), the inlined 23 KB dictionary, and the `#l=` URL. **C/V**
- `sandbox.html` (live, same origin) builds HTML from strings with `innerHTML`, including network-supplied titles and peer names (sandbox.html:226-229, 484-486). That is cross-site scripting (XSS) on the origin that stores the lists. Do not redeploy it. **C**

### 3.5 What checkpoint-1's `migrateV1` does and misses (V, harness steps C–E)

`migrateV1` (app.js:81-104) imports every list from `listolista_index_local` and `listolista_index_shared` whose `listolista_data_<id>` exists. It gives each one a new id `l_<16hex>`, keeps `meta.title` (correctly, not the index title), drops `category` and `lastAuthor`, marks the shared ones `wasShared`, and records `ll2_v1map`. It deletes nothing (good: the old keys stay as a backup). The harness confirmed:
- `listolista_v1`, `inputs`, `listolista_v2_current_*` and `listolista_library` are **left unread**. Any list that only exists in those keys is invisible after migration.
- An old shared list becomes a local list. `?local=<old>` and `?room=<old>` on the same phone open the migrated list through `ll2_v1map` (step D). On a phone without it, the app shows "Esa lista no está en este teléfono. Pide un enlace nuevo." and opens the last list (step E). The two phones that shared a list end up with two unsynced copies until someone re-shares.
- `created` is set to `i.ts || t`, and live items have no `ts`, so `created` becomes the last-modified time (app.js:92-93). The pending order of re-struck items can shift (minor).
- It scans only the index keys, not the key prefix. Lists whose index entry is missing are skipped (C).

### 3.6 Recommended import for the rebuild

1. Run once per version, under a marker key in the new namespace. Never delete or rewrite any old key: they are the rollback, and some may belong to other projects on the origin.
2. Sources, in this order:
   - (a) Every key matching `^listolista_data_` (do not rely on the index). Use `listolista_index_shared` membership, or an id starting with `room_`, to tag the list as ex-shared. Take `lastVisited` from the matching index entry.
   - (b) Every key matching `^listolista_v2_current_` (with `listolista_library` for `lastVisited`).
   - (c) `listolista_v1`, in array or object form, mapping `txt→text`, `ts→created`, `dt→doneAt`.
   - (d) `inputs`, only if it is an array of strings or of `{value, done}`. Skip empty strings, and label the list "Lista 2024" or similar.
3. Per item: `id` becomes `String(id)`; skip `deleted:true` items and empty texts; keep `done`; `created = min(id, timestamp)` (old ids are creation milliseconds, so `id` is the best creation time we have). Do not keep `category`; recompute it.
4. Title: take `meta.title` (or `title`). It is probably uppercase already (bug M2) and the original case cannot be recovered. Optionally show it in sentence case.
5. De-duplicate. Share in the live app leaves the original local list in place and creates a shared copy with identical items (main:409-421), so one phone can have two lists with the same title and the same item ids. Offer to merge lists whose item-id sets overlap, or at least label them.
6. Keep a map from old id to new id so that `?local=` and `?room=` links keep resolving on the same phone (see §4).

How the rebuild should handle them:
- `?local=X`, `?room=X` (any form) or a Trystero-style bare hash: look X up in the import map. If found, open that list and clean the URL. If not found, open the default list and say plainly that this link came from an older version and the list must be shared again.
- Do not keep `sandbox.html`.
- Option for Victor (a design call): migrated ex-shared lists could re-join automatically if the new sync key were derived from the old `room_<32hex>` id. The safer default is to re-share.

## 5. UX details worth keeping

1. **Open straight into the list, with the input focused** (main:291; app.js:585). Keep the "large tap-to-write zone" below the list (app.js:608-610, app.html:88) because iOS needs one tap for the keyboard.
2. **Input pinned at the top**, so the screen never jumps under the thumb (the README "Input Waterfall"). Pair it with feedback when the new item lands off-screen ("Añadido: X (abajo)", app.js:231-234), or put new items where the user is looking.
3. **Comma splitting with a final " y "**: "huevos, leche y pan" gives 3 items; "pan y mantequilla" stays one (app.js:211-219). Add a guard for decimal commas and split multi-line pastes (bugs C1 and C2).
4. **Tap the whole row to strike.** Struck items fold into **"Tachados (n)"** with *Limpiar* (app.js:345-354). Pending first in creation order (FIFO), struck newest first (README "Life & Death sorting").
5. **Undo instead of "¿Seguro?"**: an 8 s snackbar for delete, clear-struck and empty-list (app.js:548-555; the research cites 4-10 s Material timings).
6. **Long-press menu** (550 ms; also right-click and the ContextMenu key). One sheet with the text already in an edit field, *Guardar cambio*, *Cambiar pasillo*, and a red *Borrar* (app.js:371-386, 474-487). After the first tap, a one-time hint "Consejo: mantén presionado…" (app.js:563-567).
7. **Title editing**: inline `contenteditable`; Enter commits and returns focus to the input (app.js:603). Save `textContent`, not `innerText` (bug M2). Debounce sync by 400 ms (app.js:598-602), and never overwrite the title while it has focus (app.js:321).
8. **Back closes a sheet** instead of leaving the app (app.js:392, 412). Sheets slide up from the bottom, within thumb reach.
9. ***Compartir* as the one labelled primary action**, with the status dot inside it. Use the Web Share API first, then the clipboard, then `prompt()` (app.js:534-544). The offline note appears only after 4 s (app.js:198-208).
10. **A flash on items changed by the other phone** (the `flash` animation, which respects reduced motion: app.html:81-83; app.js:183-194). This is the visible "quantum paper" moment. The live app had an unused `.synced` green for the same idea (main:109).
11. **Aisle view as an opt-in switch**: walking order set with ↑/↓, a correction made once applies to the whole list and syncs, and guesses show with a dashed tag (app.js:270-313, 489-521; app.html:79-80).
12. **Resilience**: merge on `storage` events across tabs, a fresh connection on `visibilitychange`, persist on `pagehide`, sanitize everything read, monotonic `bump()` (app.js:29, 33-62, 613-628).
13. **Accessibility**: `role="checkbox"` and `aria-checked` on items, keyboard toggle and delete, 44 px icon targets, a focus-visible ring (app.html:42, 55; app.js:361-386).
14. From 2024 (an idea, not code): the "paper" model, where every line stays editable in place and two empty lines always wait at the bottom (local-2024:80-130). This is the ancestor of the *Papel* mock-up still waiting on Victor's decision.
15. From the sandbox (an idea): "X está escribiendo…" / "Actualizado por X" (sandbox.html:443-466, 413-418). This is optional presence that would make the shared paper feel live. It costs a second topic and heartbeats, so treat it as a later idea.

## 7. Visual style

- **Live (`main`)** (`shots/main_list.png`, `main_aisle.png`, `main_library.png`): pure black on white, `system-ui`, no dark mode (main:9-16). A fixed 50 px header with a **2 px solid black rule** and a bold uppercase title with 1 px letter-spacing (main:30-50). Full-width 55 px rows with 1 px #eee dividers, 1.1 rem text, and a grey 0.75 rem category subtitle that carries an emoji (main:83-96). Struck rows: #aaa line-through on #fcfcfc. The aisle headers are a grey band with uppercase bold labels (main:99-103). The modals are "neo-brutalist": a 2 px black border and a hard `4px 4px 0` shadow with a slight backdrop blur (main:112-126). The black pill toast sits at the bottom. The header icons are colour emoji, which are the loudest element on screen and clash with the monochrome page. The README calls the look "Pragmatic Utility"; the CSS calls it "UTILIDAD PRAGMÁTICA".
- **checkpoint 1** (`shots/cp1_list.png`, `cp1_menu.png`, `cp1_item.png`, `cp1_aisles.png`): the same monochrome DNA (the 2 px ink header rule, uppercase bold title), made calmer and with tokens: `--ink #111`, `--bg #fff`, `--dim #ececec`, `--muted #767676`, an accent `--done #1d6b45` (focus ring, switch, status dot), `--flash #dcf2e4`, `--warn #b3261e`, plus a full dark palette (app.html:28-37). A 17 px body and 54 px rows. The header has a monochrome SVG chevron and dots, and a single outlined pill *Compartir*. Bottom sheets have 16 px top corners and a 2 px ink top border. Secondary actions are underlined text links ("Cerrar", "Limpiar"). Aisle pills are rounded 12 px, dashed for guesses. The snackbar is ink-coloured with 12 px corners. The icon (src/icon.svg) is a white check plus three lines on a #111 rounded square.
- **sandbox**: a grey (#f0f2f5) dashboard with white cards, a three-column grid, coloured state borders (orange, green, red) and a dark JSON panel. It reads as a developer tool, not product style.
- **2024**: unstyled browser inputs and checkboxes.

The rebuild can inherit the checkpoint-1 token set and the "paper" monochrome with one green accent; drop the emoji icon bar.
