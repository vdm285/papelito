# ListoLista: media and type for a "piece of paper"

Research date: 2026-10-21. Scope: emoji and icon sets, handwriting and UI fonts, the paper texture, and the ink strike-through. I fetched every licence from the project's own repository or site and quote it below. Every size in this report was measured on files downloaded to `D:\_GitHub\listolista\data\cache\media\`. Where I could not check something, it says **unverified**.

Workspace (all under `data/cache/media/`):

- `dl/licenses/`: licence and README files as fetched.
- `dl/emoji/<set>/`: 11 sample glyphs per set, plus `sizes.json`.
- `dl/grocery-set/<set>/`: 148 grocery code points per set.
- `dl/fonts/`: Fontsource and Google Fonts metadata, woff2 and ttf files, `analysis*.json`, and `subset/` (my build-time subsets).
- `dl/paper/`: texture candidates and Commons/ambientCG/Poly Haven API dumps.
- `dl/libs/`: rough.js and perfect-freehand builds.
- `bench/`: `paper.html`, `strike.html`, trace results.
- `shots/`: screenshots.
- `scripts/`: every script used.

Screenshots come from an isolated headless Edge 155 started by `scripts/cdp.mjs`, with its profile under `data/cache/media/edge-profile`. Font metrics come from fontTools 4.63.

Avoid:

- **Nanum Pen Script** and **Gaegu**: no á é í ó ú ñ ü ¿ ¡ at all (verified in the full Google Fonts TTFs).
- **Icons8**: the free tier needs a visible link, forbids derivatives, and forbids letting third parties get the files as standalone files, which a static site cannot prevent.
- **Noto Color Emoji as a webfont**: COLRv1, which Safari and iOS Safari do not support (caniuse).
- **Fluent "Color"** SVGs: 164 gradients and 32 SVG filters across just the 11 samples.

### 2.2 Coverage of the requested items

There is **no Unicode code point for "tortilla"**. The closest are 🫓 *flatbread* (U+1FAD3, a round grill-marked disc that reads as a tortilla), 🌮 *taco* (U+1F32E) and 🌯 *burrito* (U+1F32F). 🫔 *tamale* is U+1FAD4. All four big sets have every requested item: avocado, flatbread, taco, burrito, tamale, hot pepper, egg, glass of milk, bread, soap, roll of paper (toilet paper), baby bottle and dog. They also all have the Emoji 15.1 *lime* sequence (`1F34B 200D 1F7E9`), corn, beans, tomato, onion, sponge, broom and cat. I checked by path in each repo tree (`scripts/find_paths.mjs`).

Across a 148-code-point grocery list (the food and drink blocks plus household items and pets, named from Unicode `emoji-test.txt` v18.0, 2026-04-30), **Fluent misses 🫜 *root vegetable* (U+1FADC, Emoji 16.0)**. Fluent appears frozen at Emoji 15.1. Twemoji, OpenMoji and Noto have all 148.

### 2.5 Identical rendering on iPhone, Android and desktop

- **Native emoji** (the old code) differ per platform by design.
- **SVG files or inline `<svg>`** render identically everywhere and are the only fully deterministic route.
- **Colour emoji webfonts** are not portable. caniuse `colr-v1.json` lists Safari 26.6–27.2 and iOS Safari 26.6–27.2 as **not supported**; Chrome 155+ and Android Chrome 155 are supported. Plain COLRv0 is supported in iOS Safari from 11.0 (caniuse `colr.json`). So the Google Fonts "Noto Color Emoji" COLRv1 font will not render on iPhones.
- **Monochrome Noto Emoji as a webfont**: plain `glyf` outlines that every engine can draw. Whether iOS Safari uses a web font listed first in `font-family` for emoji-presentation code points instead of Apple Color Emoji is **unverified**; it must be tested on a real iPhone. If it fails, ship the same glyphs as SVG (§2.3). The size is roughly 2.7× larger per icon, but the result is deterministic.

### 2.6 Build-time subsetting

- Per-file SVG sets (Fluent, Twemoji, OpenMoji, Noto SVG) are trivially subsettable. Copy only the files for code points in our dictionary, optionally run them through an optimiser (not run here; **unverified** savings), and emit `<symbol>`s or per-item files. Fluent Color needs id prefixing if inlined.
- The Noto Emoji font subsets cleanly with fontTools. `instancer.instantiateVariableFont(wght=400)` then `Subsetter` gives the 4.4 KB / 61 KB woff2 above (`scripts/analyze_fonts2.py`). A woff2 build needs the `brotli` Python module, which I installed only under `data/cache/media/pylib`.

### 2.7 Emoji recommendation

1. **Default: no icons required.** The list must work as pure text.
2. **If icons, use ink style: Noto Emoji monochrome (OFL-1.1).** Map dictionary items to code points at build time. Ship either a font subset (~0.4 KB per glyph) after testing it on iPhone, or SVG (~1.1 KB gzip per glyph, deterministic). Load lazily per item and colour with `currentColor`.
3. **If colour: Twemoji (CC BY 4.0).** It has full coverage up to Emoji 17 and is the smallest colour set (~0.67 KB gzip per icon). Ship unmodified.
4. Fluent Flat (MIT) is an acceptable colour alternative with the lightest licence burden. But it is frozen at Emoji 15.1 and ~0.81 KB per icon.

## 3. Handwriting fonts and UI fonts

Method:

- Licence, weights and variable axes come from the Fontsource API (`api.fontsource.org/v1/fonts/<id>`, `/v1/variable/<id>`) and from `google/fonts` `METADATA.pb` + `OFL.txt`.
- Sizes are the Fontsource CDN `latin-400-normal.woff2` and `latin-700-normal.woff2`, plus the variable `latin-wght-normal.woff2`.
- Spanish coverage was checked in the cmap of the latin-subset TTF. Missing glyphs in the two Korean fonts were re-checked against the full Google Fonts TTFs.
- x-height was measured from the bounding box of the "x" glyph (OS/2 `sxHeight` was wrong for Delius).
- The "build subset" column is my own pyftsubset run: U+0020–007E, U+00A0–00FF, U+2010–2027, U+2030–203A, U+20AC, U+2212; hinting removed; desubroutinised; woff2. It is reported twice: keeping kern/liga/calt/ccmp/locl/mark, and keeping kern only.

### 3.3 OFL obligations when self-hosting and subsetting

From `OFL.txt` (identical in every OFL font fetched):

> "2) Original or Modified Versions of the Font Software may be bundled, redistributed and/or sold with any software, provided that each copy contains the above copyright notice and this license. These can be included either as stand-alone text files, human-readable headers or in the appropriate machine-readable metadata fields within text or binary files as long as those fields can be easily viewed by the user."
>
> "3) No Modified Version of the Font Software may use the Reserved Font Name(s) unless explicit written permission is granted by the corresponding Copyright Holder."

A subset is a Modified Version. Kalam, Patrick Hand, Caveat, Mali, Figtree, Atkinson Hyperlegible Next and Noto Emoji have **no RFN** in their OFL headers, so a subset can keep its name. Gochi Hand, Handlee, Delius, Nanum and Lexend do declare RFNs; a subset of one of those must be renamed (e.g. `font-family: "LL Hand"`). My subset script keeps name IDs 0–6, 13 and 14, so the copyright and licence travel inside the file. Also ship `licenses/OFL-<font>.txt`.

## 4. Paper look

### 4.1 Zero-asset recipe (what I measured)

`bench/paper.html` builds seven variants on a 90-item list:

- `plain`: flat colour.
- `g`: CSS gradients only (ruled lines from `repeating-linear-gradient`, red margin from `linear-gradient`, soft `radial-gradient`, `background-attachment: local`).
- `svgbg`: `g` plus an `feTurbulence` SVG as a data-URI **background image** (300×300 tile, `fractalNoise`, `baseFrequency=.8`, `numOctaves=3`, `stitchTiles=stitch`, alpha .09). The data URI is **368 bytes**.
- `overlay`: `g` plus a fixed full-viewport `::after` with CSS `filter:url(#noise)` and `mix-blend-mode:multiply`.
- `inline`: `g` plus a fixed inline `<svg><rect filter=url(#noise)>` behind the content.
- `img`: `g` plus a real texture WebP tile with `background-blend-mode:multiply`.
- `canvas`: `g` plus noise generated once on a 256² canvas and set as the background.

**Trace measurement.** `scripts/cdp_trace.mjs` traced each variant from navigation through a scripted 120-frame scroll, 120 frames of typing and 60 strike toggles: about 300 frames, two runs each. Setup: headless Edge 155, viewport 390×844 at DPR 2.75, i5-9300H, **software raster and compositing** (Edge reported `rasterization: disabled_software`, `gpu_compositing: disabled_software`). Total ms per run:

| Variant | Compositor draw (`Display::DrawAndSwap`) run 1 / run 2 | `RasterTask` run 1 / run 2 | Image decode |
|---|---|---|---|
| plain | 115.3 / 74.1 | 24.7 / 10.4 | – |
| g (gradients) | 76.2 / 72.3 | 36.4 / 37.0 | – |
| svgbg (turbulence as background image) | 111.3 / 86.6 | 63.8 / 49.0 | – |
| **overlay (`filter:url()` + `mix-blend-mode`)** | **717.5 / 706.5** | 84.5 / 55.4 | – |
| inline fixed `<svg>` with filter | 191.8 / 113.0 | 70.9 / 44.3 | – |
| img (WebP tile) | 103.1 / 79.1 | 59.3 / 45.0 | 7.3 / 5.7 |
| canvas noise | 119.2 / 85.1 | 49.1 / 35.0 | 4.8 / 4.1 |

Reading:

- The filter-plus-blend overlay costs about **6–9× the compositor time** of every other variant, roughly 2.1–2.4 ms extra on *every* frame on a desktop CPU. It is re-filtered and re-blended each frame.
- The background-image tile costs a one-off raster (about +27 ms of raster in run 1) and then behaves like plain gradients.
- requestAnimationFrame intervals stayed at 16.7 ms for all variants, even under 4× CPU throttling (`bench/results_cpu.txt`). Throttling slows only the main thread, and this work runs on raster and compositor threads, so frame timing alone hides the cost.

**One-off raster cost** of the same turbulence SVG drawn to a canvas (`rasterTest`, main thread, cold then warm):

| Size | 1× CPU | 4× CPU throttle |
|---|---|---|
| 300² tile | 0.9 / 0.8 ms | 26.7 / 4.0 ms |
| 1080×2400 full screen | 24.8 / 26.5 ms | 598 / 134.6 ms |

So keep the noise as a small tile, never as a full-screen filter.

**Canvas noise generation** (256² plus `toDataURL`) took 61 ms at 4× throttle but 462 ms in one cold 1× run, an outlier I could not explain. It is not worth it over the 368-byte data URI.

**Mid-range Android: not measured on a device (unverified).** These are desktop software-path proxies. External evidence points the same way:

- WebKit bug [287982](https://bugs.webkit.org/show_bug.cgi?id=287982) (2025-02-19, status NEW): a grain overlay made with `feTurbulence` through `filter: url(#grain)` on an absolutely positioned `::before` made scrolling slow in WebKit. Removing the `filter` fixed it.
- Chromium's (undated, old) [Filter Effects design doc](https://www.chromium.org/developers/design-documents/image-filters/) says reference filters on HTML content render the element to a buffer and filter it on the CPU, unless the source is already a composited layer.
- CSS-Tricks "[Grainy Gradients](https://css-tricks.com/grainy-gradients/)" (Jimmy Chion, 2021-09-13) is the usual source of the noise-as-background technique.

Support: `feTurbulence` is in iOS Safari 6+ and Chrome Android 18+; `background-blend-mode` in iOS Safari 8+ and Chrome Android 35+ (MDN browser-compat-data 8.1.6, `understand/bcd/data.json`).

Visuals: `shots/paper_variants_sheet.png` (gradients, svgbg, overlay, img) and `shots/paper_grain_zoom.png`. At phone size the grain is subtle; the ruled lines and red margin carry most of the "paper" feeling.

### 4.3 Paper recommendation

1. Ship **CSS gradients plus the 368-byte turbulence tile as a `background-image`**. This is zero image assets and zero requests, and it costs one raster per tile size.
2. Do **not** use `filter:url(#noise)` on a fixed overlay, and do not put `mix-blend-mode` on a full-screen layer.
3. In dark mode, swap the tokens (paper → dark slate, ink → light). The noise alpha must drop.
4. If a scanned feel is wanted later, add ambientCG Paper001 as a 4 KB WebP behind a feature flag and compare on a real mid-range Android phone.

## 5. Ink strike-through

`bench/strike.html` (built by `scripts/make_strike_demo.mjs`) renders the same items six ways, using Kalam at 22 px; the screenshot is `shots/strike.png`. The six ways are CSS `line-through`, CSS `wavy`, my custom one-pass and two-pass generators, rough.js, and perfect-freehand.

- Keep the tap target and semantics on the row (`role="checkbox"` + `aria-checked`, per the old research `ux-patterns.md:214`).

## 7. Not verified, and other risks

- **Mid-range Android performance** was not measured on a device. All perf numbers come from desktop Edge in software raster mode. GPU-rasterised phones may behave differently in either direction.
- **iOS Safari and a monochrome emoji webfont.** I could not test whether a `font-family`-first web font beats Apple Color Emoji for emoji code points. The SVG route avoids the question.
- **`pathLength` on iOS Safari** is not in BCD. Test it, or use `getTotalLength()`.
- **The Noto Emoji licence wording is inconsistent.** The README calls the library OFL and the images Apache-2.0; the root LICENSE is OFL; `2D/svg/LICENSE` is Apache-2.0. All are permissive, but the attribution line should follow the files actually shipped.
- **Icons8**: its own licence page returned 403, so I relied on its Help Center agreement (updated 2025-11-27).
- **SVG optimiser savings** (e.g. SVGO) were not measured. I did not install an optimiser.
- **Legibility judgements** are mine, from 1× renders at 420 px width. They should be confirmed on real phones by the two testers.
